# Documentation routing for AGENTS.md

Always read `docs/PROJECT.md` first.

Then read only documents relevant to the task:

-   functional behavior → `docs/FEATURES.md`
-   schema/persistence → `docs/DATABASE.md`
-   HTTP contract → `docs/API.md`
-   PHP/code organization/CLI/cron → `docs/ARCHITECTURE.md`
-   RSS/Atom/discovery/synchronization → `docs/RSS.md`
-   authentication/security/remote content → `docs/SECURITY.md`
-   UI/JavaScript/responsive/accessibility → `docs/FRONTEND.md`
-   service worker/offline/installability → `docs/PWA.md`
-   tests/quality → `docs/TESTING.md`

Do not load unrelated specifications unless the task crosses those
boundaries.

When documents overlap, the topic-specific document is authoritative for
its subject.
